# Unified usage in Docker

Run the existing gateway as a persistent Docker Compose service, with proxy, dashboard and automatic collectors in the same process. The user authorized using the Cursor desktop session database for usage polling at api2.cursor.sh; no browser login or manual export is needed for collection.

- Claude Code: recursively scan retained ~/.claude/projects JSONL logs, including subagents. Deduplicate by message ID and keep the largest completed streaming snapshot. Show configured API-rate estimates, with the one-hour cache write adjustment. Once transcripts exist they are canonical for unified Claude totals; gateway-only history remains visible in the proxy section and is explicitly excluded from unified totals.
- Codex: scan sessions and archived_sessions. Prefer response IDs for modern records. Preserve legacy-only cumulative deltas before modern response records in mixed logs, replacing overlapping fallback identities when direct records become available. Cached input and reasoning output are subsets, not additional total tokens. Estimate per-request value using current standard API rates from LiteLLM, refreshed hourly with a persistent cache. Unknown models use an explicitly labelled Sol fallback; context tiers apply per request. Dashboard defaults to the current calendar month and retains rolling-day filters.
- Cursor: reread three allowed state database keys each poll, verify the current account with DashboardService/GetMe, then paginate GetFilteredUsageEvents filtered by that user ID. Only api2.cursor.sh receives the existing access token; no redirects, logging or credential persistence. Keep reported chargedCents separately from missing prices. RPC is the version-sensitive API used by the installed Cursor app.

Local logs refresh every 60 seconds; Cursor every 300 seconds with a rolling 365-day fetch window. Event history persists in an external_usage SQLite table, independent of gateway calls so imports cannot trigger proxy budgets. Repeated polls are idempotent. Failed sources retain old data and expose status/last successful poll instead of reporting zero.

Compose binds 8788 to loopback only, mounts usage/credential directories read-only, persists gateway data, and restarts unless stopped. Frontend assets are built into Dockerfile.local; the existing Dockerfile remains the cloud API build. No conversations, credentials, private exports, or databases enter the image/build context. Docker must be running; the host must be awake and Cursor must have a valid signed-in session.

Validation covers parser/accounting fixtures, SQLite deduplication and budget isolation, HTTP pagination/account filtering, Go suite, frontend tests/build/lint, a separate Docker database/port, and live migration with SQLite backup and launchd rollback instructions.
