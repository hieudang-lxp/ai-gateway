# Frontend Dashboard (Phase 2) — Design

Date: 2026-08-31
Status: approved
Parent spec: 2026-08-28-ai-gateway-design.md (Implementation order step 5)

## Goal

Build `frontend/`: the React dashboard consuming the already-live Connect RPC
StatsService (`Overview`, `SpendSeries`, `ModelBreakdown`, `RecentCalls`).
Scope: full dashboard working against the **local** gateway (`gateway serve`,
`http://localhost:8788/rpc`). Deploy (Netlify/Render) is step 6, out of scope here.

## Stack

- Vite + React + TypeScript + Tailwind, in `frontend/`.
- TS Connect clients generated by buf: extend root `buf.gen.yaml` with
  `buf.build/bufbuild/es` + `buf.build/connectrpc/es` plugins → `frontend/src/gen/`.
  Generated code is committed (same policy as `backend/gen/`).
- Data layer: `@connectrpc/connect-query` on TanStack Query.
  Transport: `createConnectTransport({ baseUrl: import.meta.env.VITE_API_URL })`,
  default `http://localhost:8788/rpc`. Refetch interval ~30 s on all queries.
- Charts: Recharts.

## Auth

Bearer token entered once, kept in `localStorage` (`dashboard_token`), attached
by a transport interceptor as `Authorization: Bearer <token>`. Empty token →
header omitted (local serve has auth disabled). Any `unauthenticated` response
→ clear stored token and show the token form again.

## Views (single page, sections)

1. **Budget bars** — `Overview`: today/week/month progress bars, spent vs
   warn/hard. Color shifts at warn and hard; a 0 threshold means disabled →
   show spend only, no bar limit.
2. **Spend chart** — `SpendSeries` (30 d), Recharts bar chart; tooltip shows
   cost + call count. Note: server already zero-fills missing days.
3. **Model breakdown** — `ModelBreakdown` (30 d) table: model, calls,
   input/output/cache-read/cache-write tokens, cost.
4. **Cache stats** — from `Overview`: hits, saved USD, total calls.
5. **Recent calls** — `RecentCalls` table, cursor pagination via `before_id`
   ("older" button), badges for `cache_hit` and `routed_from`.

## USD → VND

Global currency context (toggle in the header) applied to every money display.
`useExchangeRate`: fetch `https://open.er-api.com/v6/latest/USD` hourly;
last-good rate cached in `localStorage` as fallback; rate + fetch time shown
next to the toggle. Formatting via `Intl.NumberFormat('vi-VN')` for VND,
`en-US`/USD otherwise. DB stores USD only — VND is display-layer.

## Gotchas

- Connect JSON omits zero-valued proto3 fields (verified live: `spent_usd`
  disappears at 0). Generated connect-es types default these — never hand-parse.
- `int64` proto fields surface as `bigint` in connect-es — convert explicitly
  for display/charts.

## Testing

- vitest: currency conversion/formatting, exchange-rate fallback logic, and
  any data transforms (bigint → number, budget bar math).
- Manual e2e: `gateway serve` locally + real Claude Code traffic → data visible
  in every section, in both USD and VND.
